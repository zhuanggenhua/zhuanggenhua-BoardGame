# 教程与新手引导设计规范

适用于 `tutorial`、`onboarding`、教学步骤、教程 E2E、教程文案审查。本文件约束“教什么、怎么证明教会了”；截图证据回到 [`e2e-verification`](e2e-verification.md)，教程执行 workflow 回到 [`tutorial-workflow`](../../skills/tutorial-workflow/SKILL.md)。

## 落点

- 通用规范只写可复用判断方法：教学目标、章节边界、覆盖矩阵、文案来源、验收口径。
- 具体游戏的章节数、路线、固定案例、专有机制名、专有地区、起手局面和素材裁定，必须下沉到该游戏教程实现、覆盖矩阵、专项文档或 evidence。
- 准备把教程经验写进本文前，先抽象成三类角色：玩家需要获得的**信息角色**、玩家需要执行的**行为角色**、验收需要证明的**证据角色**。只有剥离游戏名、章节名、地点名、阵营名、道具名、规则书名和 UI 壳层后仍能约束多款游戏的，才能写进通用层；剥离后只剩当前实例时，落到单游戏教程实现、覆盖矩阵、专项文档或 evidence。
- 通用规范应优先给出一条正确做法，而不是堆特例警告。每条新规则必须能回答：它拦哪类跨游戏错误；它要求 agent 先做什么；它不替单游戏预写什么答案；本轮专项答案落到哪里。答不出就不得写进通用层。
- 教程正文不是规则整理入口。动手前必须先读规则真相源，并把本教程覆盖的对象、触发、玩家选择、状态变化、结果反馈、图标/素材映射列成规则合同；合同缺口先补或登记，不能用泛化文案绕过。

## 正确交付路线

教程重构默认先按一条正向路线执行，再用后文红线兜底。目标不是列出一堆错误做法，而是交付一条玩家能自然跟完的教学链：

1. **锁定玩家要学会的流程**：从规则真相源和正式 UI 中确定本教程的目标、胜负条件、当前玩家身份、第一段正式决策和必要读局信息。
2. **画出玩家因果链**：把流程写成 `上一画面状态 -> 当前玩家输入或系统自动结算 -> 规则后果 -> 下一入口`；每个节点都对应真实画面、真实权限和真实对象。
3. **把教学内容挂到第一次看见的节点上**：基础读数、卡面字段、房间 / 区域类型、随机结果、确认语义、改骰 / 重掷、只读帮助和结果反馈，只要第一次进入玩家视野就开始教学；当场不需要完整使用时，先教基础识别和读法，等真正使用时再补目标、限制、结算等使用判断。
4. **默认合并成一条自然主线**：能沿同一玩家因果链讲清的机制放在同一教程里。只有视角、权限、私密信息、控制者、规则前提或局面来源真实断开时，才拆成独立章节、专题或分段证据。
5. **按交互族设计 UI 状态**：每类交互都串齐入口、候选态、选中态、提交 / 确认态、结果态和退场 / 下一入口；同一游戏同类确认、选择、结果反馈优先复用同一个组件或视觉语法。
6. **文案只讲当前节点**：每张教程卡只说明当前目标、当前对象、当前动作或当前结果。规则解释来自规则书 / 卡面 / 已锁定真相源；未决分支只在真实选择窗口讲。
7. **用真实截图闭环**：E2E 按玩家顺序截图，每张玩家可见教程卡都有对应画面；相邻截图能说清承接动作，动态步骤能看出屏幕变化，结果层继续走到下一可操作入口。

收口时先问这条路线是否完整，再看覆盖矩阵、红线和最低验收。若路线本身讲不通，优先修流程、UI 承接或章节边界，不先补更多警告句。

## 开工门槛

新建、重做或收口教程前，至少先列三张表：

1. **规则覆盖矩阵**：规则条目、教程章节/步骤、真实承接物、E2E 操作、截图证据、状态。
2. **玩家可用元素矩阵**：元素名称、现实职责、正式 UI 位置、基础读法、是否影响首局决策、教程/帮助落点、端到端证据、未覆盖原因。
3. **主要交互清单**：当前同层一级行动全集、真实主入口、支付/弃牌、目标选择、随机/揭示、结算、等待/收口；每行区分 `真实承接物` 和 `提示 UI`。

矩阵只写“已介绍”不合格。被教程文案点名的入口，必须有真实操作和截图证据；被正式 UI 常驻展示且会影响首局决策的基础读数，必须说明玩家如何读它、它何时变化、截图或断言在哪里；缺证据只能标 `待补端到端证据`。

卡牌、角色卡、帮助卡、骰面、token 或其它图标密集对象会在正式流程中反复出现时，必须把“图面字段 / 图标含义”作为玩家可用元素过账。过账至少写清字段现实含义、正式 UI 位置、首次教学时刻、后续是否复用、以及不重复教学的依据。只让玩家点击对象，不教他读费用、目标、类型、范围、等级、状态、攻击条、生命 / 护甲或等价字段，不能算该对象已被教程覆盖。若用户、规则书、官方页或帮助卡给出一组图例 / 截图，必须先逐张判定是否只是重复字段；凡是补充了新字段、新读法或特殊子结构的图，例如攻击条、装备部位、展示费用、范围 / 目标例外等，都必须进入首次教学、帮助入口或覆盖矩阵的明确暂不覆盖项，不能只接入第一张图后宣称图面含义已覆盖。首次教学时刻以字段第一次真实出现在玩家视野为准；若此时还不要求玩家使用，只教这是什么、在哪里读、当前状态代表什么，等第一次影响判断或即将被使用时再补目标、限制、结算等使用判断。不得等到攻击、结算或正式点击时才第一次介绍已经可见的攻击条、生命 / 护甲、部位、隐藏 / 展示方式等字段；也不得在流程前段把后续才出现的字段一股脑预讲成图例清单，或把“本教程为什么这样安排”“后续怎么复用/判断”写给玩家。

教程文案必须绑定当前画面的真实视角、owner 和承接物。文案说“对手 / 队友 / 另一名玩家 / 公开信息”时，高亮、截图和断言必须落到对应玩家拥有或对应视角可读的真实对象；不得用当前玩家自己的同类区域、同名牌堆、摘要条或泛化容器冒充对方信息。教程讲“看对方弃牌 / 牌库 / 装备 / 持有物 / 公开区”时，默认先让玩家执行或看到视角 / 观察对象切换，再高亮切换后的同一主槽位；不得新增代理 UI、平行对手槽位，或在己方槽位文案里声称那是对方信息。若规则确实要求双方公开区同屏比较，必须把该比较任务写进覆盖矩阵，并证明它不是为了补教程可见性临时新增的副本。

合并、删减或重排教程前，必须先做**教程内容总账**：把旧教程、规则书和正式 UI 中已经承载的核心机制、可用动作、可读信息、随机/揭示结果、视角差异、分支补充和帮助入口逐项列为 `主线自然教学`、`分支/补充教学`、`帮助/信息承接`、`暂不覆盖并说明` 或 `待补缺口`。合并只允许改变教学容器和出现顺序，不能让机制、卡牌使用时机、交易/交换、类型映射、确认语义、帮助入口、信息承载物或视角信息无声消失；移出默认主线时必须写明它的新教学时刻、真实入口和证据。

用户连续指出“这里跳了”“内容是不是没了”“为什么又重复”“是不是规范问题”这类教程问题时，不得继续逐点修一个步骤。必须先回到内容总账和相邻步骤账本，证明每个保留步骤都有新增教学职责、每个被移走内容都有新落点、每个相邻截图都有真实过渡，再继续改实现或截图。

用户指出某一步“突然出现 / 前后没关系 / 不知道为什么要做”时，默认先判为规则前因或当前画面承接缺失，而不是文案不够长。最低处理顺序是：回到规则书 / 卡面原文找触发条件和前置对象，补流程原子账里的上一原子和下一原子，再决定是并回自然流程、拆成独立专题、还是标为规则原文缺口。禁止用“桥接说明”“为了演示”“现在看一下”把没有前因的代表态接回主线。

教程和游戏 UI 同时改动时，必须先做**教程-UI 联合过账**：教程步骤点名的每个对象、按钮、牌面、骰子、地图位点、确认入口和结果反馈，都要在 UI 的玩家任务与元素职责总账中找到唯一承接物；同一交互的候选态、选中态、确认态和结果态必须能按玩家动作顺序串起来。若 UI 只有局部按钮能点、截图缺相邻过渡、或教程靠说明句补一个看不见的状态，先修 UI 职责或步骤顺序，不能继续补单句文案。

规则流程拆分必须先过**流程原子账**：`触发 / 入口 -> 亮相 / 候选对象 -> 中间玩家决策 -> 提交 / 确认 -> 规则后果 -> 下一入口`。方向、旋转、路径、目标、数量、顺序、模式、放置方式、是否执行等中间玩家决策不得因为能和下一步放在同一章节里就被吞掉；可以合并在同一自然教程容器中，但必须有独立教学时刻、真实 UI 承接和截图 / 断言证据。

流程原子账必须以规则真相源的时序为锚。规则源逐条列出的步骤，只要会改变玩家可见对象、可操作控件、选择空间、提交内容或下一结算来源，就要登记成独立原子；截图编号、测试 helper、教程章节标题和旧 evidence 不能反向压缩规则时序。相邻两个规则后果之间没有新的玩家选择、响应或授权时，可以在同一教学时刻合并讲，但必须写清前一动作如何自动导致后一结果。

同一轮教程重构已经暴露两个以上相邻问题时，必须切到**教程 + UI 标准化审查**，不能继续“用户指出一处就修一处”。最低动作是：先冻结主线玩家因果链；列出教程内容总账、交互族链路账、UI 元素职责账和截图过渡账；逐项裁定合并、分支、帮助入口或暂不覆盖；再按账本改教程、UI、测试和证据。任何实现补丁、截图 PASS 或汇报结论都必须能指回这四张账中的对应行。

**教程 + UI 标准化审查**的四张账最低列如下，缺列时不得宣称已完成整族重构：

- **教程内容总账**：教学内容、规则/卡面来源、旧教程落点、新教程落点、主线 / 分支 / 帮助 / 暂不覆盖裁定、是否发生覆盖退化、对应 E2E 或截图证据。
- **交互族链路账**：交互族、入口从哪里出现、玩家看到哪些候选、玩家如何选择、是否需要确认、确认提交什么、结果显示在哪里、何时退场、复用哪个组件或视觉语法。
- **UI 元素职责账**：元素名称、唯一玩家任务、默认态 / 候选态 / 选中态 / 确认态 / 结果态、是否同源复用、可读 / 可点保护对象、退场或收纳条件、证据。
- **截图过渡账**：上一帧玩家看到什么、玩家实际输入或系统自动结算是什么、下一帧为什么出现、是否同一自然流程、若不是主线则所属专题 / 代表态分组。

## 教学不变量

- **先教读局和赢法**：玩家结束基础教程后必须能读懂首局所需的基础信息，并能说出目标、核心收益和一回合大致在做什么。
- **教动作价值**：每个正式行动至少说明它解决什么现实问题，例如补资源、抢目标、压损失、推进结算。
- **给真实收益**：基础教程必须包含一个真实局面、一次玩家选择、两个以上有因果关系的动作、一个可见收益；只证明流程能走通不算教程合格。
- **覆盖基础读数和结果反馈**：玩家要看到生命、伤害、资源、回合收入、行动可用性、分数、战力、控制权、位置或其它核心状态如何读、何时变、为什么变，不能只看日志或“成功”摘要。
- **卡面 / 图标含义第一次看见就开始教**：卡牌、角色卡、帮助卡、骰面、token 或图标是首局决策依据时，基础教程必须在该字段第一次进入玩家视野时给一次真实图面读法，再让玩家用它行动。首次出现只需要基础识别时，先讲这是什么、在哪里读、当前状态代表什么；第一次影响判断或即将被使用时，再补目标、限制、结算后果或例外。若已有规则书、官方页、帮助卡或用户确认截图能直接说明字段含义，首次教学优先用真实图例 / 截图加极短文案，而不是把整套字段改写成长段说明。成组图例必须逐张判重；只重复同一字段的图可以不重复教，补充特殊子结构或新字段的图必须在遇到对应对象时单独承接，或登记暂不覆盖理由。重复字段只在首次出现时教一次，后续只讲当前对象新增的使用差异；不得等到攻击或结算动作才第一次介绍已经可见的攻击条，也不得在第一个决策前一股脑预讲后续才出现的字段或完全不讲。
- **动作与交互同源**：教程要求玩家执行的动作，必须是正式对局里同一视角、同一阶段、同一对象上真实存在的动作；正式游玩点卡牌 / 棋子 / 地图 / 按钮，教程就点同一个真实对象。不得为了教学、截图或压流程，新增正式流程不存在的代操作、假确认、假跳过、圆点、编号、隐藏锚点、假按钮链或说明壳层。
- **步骤必须有逻辑前因**：每个教程步骤都要能从上一帧的玩家状态或规则自动结算自然推出，并能指回规则书、卡面原文或当前画面已经出现的对象。若玩家会问“为什么突然要做这个”，默认是规则前因、对象来源或截图过渡缺失；先补自然前置、拆独立专题或删除该步骤，不得用一段解释把突兀步骤留在主线。
- **动作主体和对象来源必须保真**：同一个对象可能被玩家、队友、怪物、系统结算或奖励分支带走 / 持有 / 生成时，教程必须区分真实执行主体、触发规则和结果状态；不能把怪物移动后的自动携带写成玩家拾取，也不能把预设局面里的已有对象写成上一帧自然获得。截图名、提示标题和 PASS 清单都要同样保真。
- **玩家权限同源**：教程里要求玩家执行的每个点击、选择、确认、移动、探索、阶段推进或视角操作，必须属于当前控制玩家在正式对局里真实拥有的权限。多人游戏中，当前玩家不能被教程要求代替队友、对手或另一座位完成其私有回合、私有确认或独立决策；这些前置若必须发生，只能表现为等待、公开结果、AI / 系统按正式命令自然推进，或拆成明确的独立视角章节。切换视角只能教学该视角可读的信息或该章节的真实控制者，不能混入当前玩家自然主线来补前置流程。
- **默认主线优先多数 / 常规视角**：基础教程、首个教程和默认端到端图组必须优先教学多数玩家、常规职责、公开信息和普通首局心智路径。少数身份、敌对阵营、叛徒 / 内鬼、隐藏角色、私密信息承载物、秘密目标、低概率特殊身份或只属于个别玩家的特殊回合，不得作为默认主线的第一视角；只能作为独立章节、补充专题或明确标注的分段证据。若某条自然规则会让当前玩家进入少数身份，就不能把它继续包装成“普通玩家主线”，必须改成多数视角自然观察 / 等待公开结果，或拆成少数视角章节。
- **先同步正式流程**：教程步骤不得先于正式游戏流程成立。若正式对局中无决策阶段应自动结算，先修正式流程自动推进；若正式对局中玩家要点击“完成当前阶段 / 进入下一阶段 / 跳过当前窗口”，教程必须让玩家点击同一个真实控件，并断言阶段前后状态。阶段按钮即使外观相同，只要阶段、权限、对象、结果或下一入口不同，就不是可压缩的重复操作。
- **自然流程优先于代表态**：教程承诺“跟流程自然教学 / 端到端”时，必须让前置条件通过正式回合、玩家动作和系统结算自然形成。第一步前可以锁定最近合法起点、牌堆顺序或随机结果，但进入玩家可见链后，不得直接发牌、改持有物、切结果态或用代表态补洞来替代前置流程。若截图或教程突然跳到后果态，首要修正对象是流程起点、可见玩家动作、系统自动结算和 E2E 链路；不得用调提示词、改标题、补说明句或换截图命名来替代自然流程。确需分段时，只能标为分段 / 代表态证据，不得接入主线连续图组或称为自然端到端。
- **信息承载物 / 阶段切换不是自然链终点**：自然流程触发新的身份、目标、胜负条件、阶段说明、结算页或等价模式切换时，信息承接只证明“玩家知道当前目标或模式变了”，不能证明切换后的玩法已经教会。默认必须继续到切换后第一个真实玩家决策、正式动作或结果反馈；若后续视角、权限、规则前提或局面来源已经断开，必须拆成独立章节或分段证据，不能把代表态后续接成连续主线。
- **一次性情境信息只首看，回看聚焦当前决策信息**：教程使用阅读界面、帮助入口、阶段说明、目标说明、卡面详情或其它信息承载物时，先区分一次性情境信息与可重复决策信息。首次触发时，一次性情境信息只完整出现一次，并自然承接到玩家下一步需要理解的目标、限制、行动或结果；需要继续阅读时，翻页必须让玩家看见后一页为什么是当前画面的下一项信息。完成首次阅读后，默认回看进入当前决策仍需要的目标、规则、限制、状态或入口，不重播一次性情境信息；若某游戏确实支持历史说明回顾，应作为明确回顾入口，不占用正常回看。内容来源、视角范围和已教过的阅读顺序必须同源，不能让首次阅读与回看出现不同规则、不同视角或内容丢失。回看默认页属于独立回归验证；除非当前教程明确要教玩家如何回看规则，否则不得把回看插成自然主线的玩家可见步骤或主流程截图。E2E 至少覆盖首次打开、必要翻页、信息承接、关闭回到下一可操作入口，并用独立断言或独立图组验证回看默认页是否符合当前决策。
- **流程原子不能吞并**：教程可以把同一玩家因果链合并为一个章节，但不能把规则流程里的独立玩家判断合成一句确认文案。只要规则要求玩家先看到候选对象再决定方向、旋转、路径、目标、数量、顺序、模式、放置方式或是否执行，教程和截图就必须先展示候选和决策控件，再展示提交 / 确认和后果；确认后的结果图不能倒证明前面的决策已经被教会。
- **自动后果可以合并，决策不能合并**：一次提交后连续发生的规则后果，例如对象效果结算、符号触发、抽取 / 翻出对应对象或状态更新，可以放在同一说明和截图里教学，前提是中间没有新的玩家判断。只要中间存在新的选择、旋转、目标、数量、顺序、是否执行、共同确认或响应窗口，就必须先教这个决策 UI，再进入后果说明。
- **单步只承接当前输入或结果**：一个玩家可见教程步骤只能对应当前屏幕上的下一次真实玩家输入，或当前必须阅读的一项单一结果。分类 / 筛选、翻页、选择对象、选择目标、调整数量、确认提交、关闭返回、视角切换和阶段推进，只要承接对象、权限、结果或下一入口不同，就必须拆成独立教学时刻或让系统自动承接；不得把多个“再 / 然后 / 接着 / 下一步继续”的后续点击和后续效果解释塞进同一张教程卡。只有动作类型、承接对象、规则效果、权限条件和后续状态都完全相同的重复操作，才允许压缩，并必须在 E2E / evidence 写清等价依据。
- **动态列表不写死历史路径**：卡池、手牌、法术书、单位列表、弃牌堆、地图区域或等价动态集合的教程步骤，必须按当前真实页面状态决定。目标对象已经可见时，不得保留“翻页 / 筛选 / 查找”步骤；目标对象不可见时，教程和 E2E 必须断言本次点击后目标真的出现，再进入选择目标步骤。禁止把旧排序、旧分页、测试 helper 的固定点击次数或历史截图路径写成玩家要执行的教程动作。
- **对象高亮要命中本体**：文案点名“这张牌/这个目标/这个地区”时，高亮和点击锚点必须落在同一对象本体；整区高亮不能冒充单对象目标。
- **选中态可逆可见**：先选对象再确认的流程必须有未选、已选、取消/确认后三态证据；单击即结算时，文案必须说清“点击后立即生效”。
- **非直觉 UI 要过账**：多次确认、观察/聚焦、等待归属、重掷/改骰、只读规则入口、隐藏可恢复区域等，必须在矩阵中标为 `流程中教学`、`帮助中解释`、`明确豁免` 或 `待补缺口`。
- **随机/揭示要展示本体**：投骰、翻牌、抽牌、亮出事件、结算型揭示必须显示骰面、牌面、对象名、效果区或等价正式承载；教程气泡和日志不能替代主结果。
- **类型到结果必须过桥**：当规则里存在“来源类型 / 图标 / 标记 / 槽位 / 区域属性 -> 对应牌堆 / 对象 / 结果”的映射时，教程必须在结果出现前后明确展示这个映射的来源、触发动作和对应结果；截图链不能从来源状态直接跳到结果牌、结果对象或下一专题。教学顺序必须是玩家先看见来源类型，再执行或看见触发动作，再看到对应结果；结果已经出现后才倒讲来源，或两个连续截图之间缺少触发/承接说明，都按跳步骤处理。若进入的是补充专题或预设局面，首帧必须说明它承接哪一种类型映射、为什么不是上一帧的直接后果；没有可见来源或触发证据时只能标为 `待补端到端证据`，不能判定 `PASS`。
- **相邻截图必须有过渡动作**：教程截图组里的每两个相邻编号都必须能写出“上一帧玩家看到什么 -> 玩家实际做了什么或系统自动结算了什么 -> 下一帧为什么出现”。若两个编号之间没有可见触发、承接说明或真实自动结算证据，即使截图各自好看，也按流程跳步处理，不得作为端到端教程 `PASS`。
- **动态截图必须有屏幕位移**：教程截图要证明重掷、移动、翻页、飞行、转移或其它动态过程时，断言必须落到玩家实际看到的屏幕投影、像素位置、目标本体或连续关键帧变化；内部 motion、计时器、DOM 标记、canvas 存在或最终状态不能替代肉眼可辨的中间帧。若过程帧与前后帧看不出变化，先修动画幅度、等待点或截图采样，不得改文件名或说明文字冒充动效。
- **展示图组也必须直接承接**：给用户打开的有序教程 / E2E 图组本身就是玩家看到的证据，不能只在隐藏 manifest、报告正文或文件夹名里说明“这里其实断开”。若两张相邻图来自不同专题、代表态、预设局面、不同视角章节或不同规则链，必须拆成独立图组或在用户可见首帧明确作为新分段起点；不得让连续编号暗示它们是上一帧的自然后果。仅把过渡文字写成“不属于主线”但仍排成连续流程，视为截图证据失败。
- **教程卡必须前景可读**：教程讲阅读界面、卡牌详情、骰盘结果、事件面板或其它浮层时，教程卡和被讲对象必须在同帧前景可见。若教程卡被被讲对象盖住、只在 DOM 中存在、或只能靠测试选择器推断它出现过，该步骤证据无效；必须调整层级、挂载点或步骤顺序后重拍。确认前景可见要进入 E2E / 截图断言，不能靠人工事后解释。
- **玩家可见文案逐卡截图**：用户要求逐步截图、逐句确认或教程截图收口时，每一张玩家实际能看到的教程提示卡都必须有一张当前主流程截图，且截图发生时该提示卡文本就是当前步骤文本。纯 AI / 系统自动桥接步骤只有在运行时不渲染提示卡、并由 E2E 断言其不出现在玩家可见流程时，才允许不截图；否则必须按可见步骤截图。动作后的结果图只能证明截图时正在显示的那张提示卡，不能倒算覆盖上一张“点击某对象”的提示卡。
- **证据编号服务玩家流程**：端到端教程截图的主编号必须按玩家实际游玩顺序排列。补充专题、代表态、失败诊断、移动端对照和截图细节可以另起前缀或分组；不得把后补截图插成远离当前位置的编号，再在 manifest 里解释它其实属于前面的自然流程。
- **局部重开必须重建局部范围**：用户点名“只看某一步之后 / 某段流程 / 后续流程”时，必须按该范围重建用户可见图组、索引和 PASS 清单；不得复用包含更早步骤或无关辅助图的全量清单来开图。局部首帧必须说明它从哪一个真实流程点接起；若首帧本身不是上一帧自然后果，只能标为专题 / 代表态起点，不能称为端到端延续。
- **文案来自规则和当前画面**：玩家文案只写规则动作、对象、结果和必要 UI 动作；不得混入测试、审计、实现关系、E2E、队列、pending、运行态等验收话术。
- **规则解释只取真相源**：除必要 UI 操作句、当前局面指向和短过渡句外，玩法、机制、卡牌效果、目标限制、状态结果和胜负解释必须直接来自规则书原文、卡面原文或已锁定规则真相源；缺原文时标 `待补规则原文`，不得用作者解释、策略判断或实现说明填坑。
- **提示与操作分工**：提示 UI 负责“看哪里/为什么”，真实承接物负责点击、选择、确认；横幅、状态条和教程卡默认不是主交互入口。
- **结果展示与共同确认分工**：投骰、翻牌或其它随机结果出现后，必须先保留结果展示窗口，让相关玩家看清结果；“确认”表示玩家已看清并允许流程继续，不等同于主动触发动作本身，也不是所有公开结果都必须多人逐个确认。是否需要确认要看展示窗口之后是否仍有相关玩家需要额外观看确认、响应、选择或授权；若触发玩家主动开始投掷后，结果已在正式 UI 保留足够阅读时间，且没有新的玩家响应、选择或授权需求，可以由运行时自动推进。若仍有共同读牌、私密/公开承接、响应或选择，必须保留对应确认，确认人数按真实参与者裁定，不按全员默认。
- **结果层不是收口态**：教程或端到端图组教学一次投骰、翻牌、抽牌、攻击、治疗、资源变化或其它结果时，结果主体截图只证明“结果看见了”；若结果层、确认按钮、选中态、阻塞遮罩或临时高亮仍在场，必须继续到关闭 / 确认 / 自动退场后的下一可操作态，才能作为该交互族收口。像 DiceThrone 黄金链这类完整流程，对应截图必须覆盖结果后回到阶段推进、下一动作、弃牌、回合交接或其它真实后续入口；不能把“结果显示出来”当作教程已经结束。
- **未决分支不得写成结果**：投骰、攻击、翻牌或其它结算结果页只能描述已经发生的事实、差值、阈值和已开启的后续机会。规则包含“可以 / 选择 / 或 / 代替 / 偷取 / 防止”等未决分支时，结果摘要、教程卡、日志和截图标题不得写成目标已经决定要执行哪一支；真正的分支文案必须等到下一真实选择窗口，并用对应 UI、断言和截图证明玩家是在那里做选择。
- **连续步骤不得复读**：同一自然流程里的连续教程步骤，如果玩家状态、可操作对象、结算阶段或结果反馈已经变化，正文必须只讲本步骤新增信息：当前目标、当前对象、当前动作、当前结果或等待原因。前一步已经讲清的机制只能用短承接词带过，不得整段复用、换序复述或把多个后续动作提前讲完。

## 自然流程与章节边界

- 基础教程默认先用一条自然玩家流程教完：目标、第一段真实决策、真实案例和结果反馈都是覆盖职责，不是四个固定章节。能在同一条玩家因果链里自然教完，就不拆章节。
- 只有一条可见基础教程时，`/tutorial` 必须直接进入该教程；不得显示目录页、推荐标签、进入按钮或完成徽章来制造伪章节。目录页只服务两个以上真实可选教程、视角或专题。
- 章节边界只在玩家心智任务真实断裂时出现，例如视角、权限、规则前提、局面来源或控制者发生变化；不得按 reducer、面板、素材目录、程序模块、截图数量或机制清单命名章节。
- 章节是教学容器，不是完成指标；章节数、截图数或机制数不能证明教程完整。完成判断只看覆盖矩阵、真实流程、玩家能否读局和端到端证据。
- 分章节必须写明“为什么不能继续用当前自然流程教完”。说不出视角 / 权限 / 规则前提 / 局面来源 / 控制者断点时，默认合并回自然流程。
- 对手、队友或系统的纯自动前置动作，不得停成玩家可见教程页；只能通过正式 AI / 系统命令自动推进，并在下一条当前玩家需要读或操作的步骤中承接公开结果。只有需要玩家观察等待原因、切换视角或进入另一真实控制者教学时，才可变成可见分段。
- **必须分章的情况**：某段教学需要切换到少数身份 / 敌对阵营 / 叛徒或内鬼、阅读私密目标或私密信息承载物、执行当前主线玩家没有权限的动作、换成另一个真实控制者的回合决策、使用不能由主线自然到达的代表态，或会把多数玩家默认心智改成低概率 / 特殊职责时，必须拆成独立章节、补充专题或分段证据。默认主线可以等待并观看队友 / 对手按正式规则产生的公开结果，但不能把这些动作写成当前玩家的连续输入。
- 核心机制默认是覆盖项和教学时刻，不默认独立成章。守卫、治疗、状态移除、墙体、响应窗口、附件目标选择等机制，只要能在同一条自然玩家流程里顺带讲清，并且各自有真实承接物、操作 / 结果证据和文案来源，就应合并在该流程中教学；不得为了“一个机制一章”、截图便利、派系统称、测试便利或显得结构完整而硬拆章节。
- 多个机制合并教学时，必须在覆盖矩阵里写清每个机制的首次教学时刻、玩家动作、画面承接和结果证据；若合并后其中任一机制被一句话带过、没有操作证据、没有结果反馈，或玩家会把不同机制混淆，才拆成独立章节或独立续段。
- 同一基础回合链中的基础读数、资源使用、目标选择、主行动和结果反馈默认合并教学；只有战斗、区域占领、外交、季节结算、终局计分等会打断当前玩家心智链、需要新局面或新规则前提的系统，才适合单独成章。
- 命名为“完整回合/基础回合/首回合”的章节，必须从正式主入口走到该主循环的主要公共推进节点结束；后续章节不能重复讲这条链的基础用法。
- 每个核心机制只能有一个主教学时刻。后续章节只能复用、补分支或讲进阶，不得平级重教。
- 刷新会丢教程进度、长链不稳定或局面难复现时，先修正式流程、保存恢复、测试等待和可重放起点；只有短期确实无法稳定自然链，才允许拆成明确分段证据。分段必须说明断点前玩家自然流程到达哪里、断点后为什么不是连续主线，不得用章节化掩盖链路断裂。
- 用户要求先看文案、章节结构或覆盖矩阵时，不得抢跑修改运行态教程、语言包、测试或 E2E。

## 文案规则

- 教程第一句只讲 `目标 + 最基本回合动作 + 结束/胜负条件`，必须短。
- 判断提示和操作提示可以拆开，也可以合并；拆分只在能降低理解负担时使用，不能机械制造重复步骤。
- 每一步文案至少承担一项职责：讲当前目标、指出收益、点名对象、说明结果。空过渡句和“现在看这里”式无信息句不合格。
- 连续步骤的首句必须能看出本步骤和上一/下一步骤的差异；若删掉步骤名后两步正文仍像同一段说明，视为文案失败，不能靠 E2E 通过或截图数量收口。
- 图面字段文案在字段第一次进入玩家视野时先给基础识别；需要玩家理解并使用时再补完整判断。若首次教学使用真实图例 / 截图，E2E 必须断言图片真实渲染且 alt 或说明能对应当前教学目标和当前画面承接物；成组图例还必须断言每张被判定为非重复的关键图在对应字段第一次出现时已经渲染，或在覆盖矩阵中有明确落点。若后续对象的类型、费用、目标、攻击条、生命 / 护甲、部位、隐藏 / 展示方式或等价字段会改变结算，必须讲清这一个新增差异，而不是重讲整张图例。
- 脚本化示范题可以点名当前牌名、目标和动作，但必须基于真实预设局面；不得脱离牌面空讲策略。
- 当前状态没有清楚承载时，先补正式 UI 表达，再写教程；不能用三句以上说明文替代牌面、棋盘、数值变化本该表达的判断。
- 规则原文、卡面、参考页已经表达当前触发或结果时，优先引用正式表达；只补最短玩家动作，例如“读完后点确认”。
- 改写规则原文只能做最小语序、代词或当前对象替换；不得新增规则源没有的价值判断、策略收益、UI 设计理由、实现原因或验收解释。目录描述、章节开头和完成句同样遵守本条。
- 规则动作、状态和结果名必须保留规则源身份：步骤标题和按钮旁提示优先使用规则动作短名或规则原文；结算后才出现的状态、标记、token 或结果只能写成结果描述，不得写成点击前的技能、目标或候选。UI 独有说明只补位置、点击/关闭方式和当前画面承接，不得用整段作者解释替代规则原文。
- 禁止把作者话术、设计意图、验收要求、防回归说明、实现结构、后续复用策略或坐标判断口径写给玩家看；这些只进测试、审计、专项合同或证据。玩家可见文案只保留规则原文 / 卡面原文、当前画面要看的对象，以及完成当前步骤所需的最短操作说明。
- 中英文教程语言包变更后，必须扫描并测试拦截实现容器词、内部流程词和作者旁白腔；E2E 通过不能替代文案门禁。

## 重构与删减

- 合并章节、删除旧步骤、压缩隐藏续章或替换教程结构前，必须列覆盖差异表：旧结构覆盖了什么、新结构落到哪里、哪些有等价真实入口、哪些退化为缺口。
- 覆盖退化必须直说 `覆盖退化/待补回`；不得用“结构更紧凑”“后续优化”包装后继续称完整。
- 不得把“合并成一条自然流程”误解为删掉不适合当前截图的机制。若某个机制暂时不进主线，必须把它留在分支、帮助或覆盖矩阵中，并说明为什么玩家不需要在本段自然流程里学习它。
- 计划文档、implementation-map、章节草案和覆盖矩阵只说明准备怎么改，不能证明当前运行态已经可用。宣称“已实现”必须回到当前源码、真实页面截图或 E2E。
- 过时覆盖矩阵与当前 `tutorial.ts`、目录显隐、E2E 截图链冲突时，矩阵是待修订对象，不能反向覆盖当前源码。

## 偏离时的纠正动作

发现教程链路不顺时，按“把它拉回正确路线”处理，而不是继续堆反向规则：

- **只跑通按钮**：回到玩家目标、动作价值和结果反馈，补齐玩家实际学会了什么。
- **章节像模板**：回到玩家因果链，合并能自然连上的机制；拆章只用于视角、权限、私密信息、控制者或局面来源断开。
- **对象或入口不真实**：回到正式 UI 的真实对象、真实权限和真实动作；测试牌、占位对象、代操作和教程专属入口只能先删出主线或改成独立专题。
- **说明比画面多**：先补 UI 承接物和状态表达，再压缩教程文案到当前节点需要的一句话。
- **确认、预选或分支语义不清**：回到交互族状态链，区分候选、选中、提交、结果、未决选择和退场；未决分支只在真实选择窗口讲。
- **截图接不上**：回到相邻截图过渡账，补真实玩家输入或系统自动结算；不同专题、代表态或预设局面用独立图组，不接成连续主线。
- **证据外推**：回到本轮覆盖矩阵，截图、历史 PASS、测试绿灯只证明它直接覆盖的节点；未覆盖项保留为 `局部完成`、`待补缺口` 或独立后续项。

## 最低验收

教程收口前，至少能用玩家语言回答：

1. 这游戏怎么赢？
2. 第一段真实决策是什么，为什么选它？
3. 玩家刚才具体赚到、造成、推进或改变了什么？
4. 哪个对象让结果变好，玩家能否在画面里看见它？
5. 计分或胜负核心是否出现过一次可见因果？
6. 非直觉 UI 和玩家可用元素是否已在矩阵中过账？
7. 是否有真实教程 E2E 和关键截图，证明玩家从目标、操作、特殊 UI、结果反馈到收口态都走过？

任一项答不出来，教程只能称 `局部完成` 或 `待补缺口`，不能称完整教程或新游戏整体收口。
